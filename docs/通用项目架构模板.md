# ManiMind 项目架构设计

保留原文件名是为了不打断现有引用；本文件的实际内容已经切换为 ManiMind 的项目架构。

## 一、目标

输入：

- 论文 PDF
- 用户笔记
- 目标受众与风格要求

输出：

- 研究总结
- 讲解脚本
- 分镜与镜头任务表
- Manim 公式动画代码
- HTML 科普片段
- 审核报告
- 配音、字幕、拼接后的交付素材

## 二、总架构

```text
预启动层
  ├─ 文档/配置加载
  ├─ 外部能力注册
  └─ 环境检测

主 Agent 层
  ├─ 输入归档
  ├─ PDF/笔记解析
  ├─ 研究总结与项目状态生成
  └─ 长期上下文写入

二级协调 Agent 层
  ├─ 脚本规划
  ├─ 分镜切分
  ├─ 工具选择
  └─ 子 Agent 分发

执行 Agent 层
  ├─ 子 Agent 1：HTML 动画
  ├─ 子 Agent 2：Manim 数学动画
  └─ 子 Agent 3：SVG 动画预留接口

审核 Agent 层
  ├─ 数学正确性检查
  ├─ 叙事完整性检查
  ├─ 时间轴一致性检查
  └─ 渲染可执行性检查

后处理层
  ├─ 配音
  ├─ 字幕
  ├─ 剪辑拼接
  └─ 输出打包
```

## 三、角色定义

### 1. 预启动器

职责：

- 读取 `docs/`、`configs/`、项目级约束
- 检测 `python`、`ffmpeg`、`manim`、`node`、`bun`
- 注册外部能力路径

输出：

- 环境检测报告
- 项目配置快照

### 2. 主 Agent

职责：

- 接收论文、笔记和用户要求
- 提取论文结构、核心结论、公式、术语、风险点
- 产出面向后续 Agent 的研究总结包

输出：

- `research_summary.md`
- `glossary.json`
- `formula_catalog.json`
- `project_state.json`

### 3. 二级协调 Agent

职责：

- 把研究总结映射为讲解脚本与分镜
- 决定哪些镜头适合 Manim，哪些镜头适合 HTML，哪些镜头需要 SVG
- 生成并发任务表

输出：

- `narration_script.md`
- `storyboard.json`
- `worker_tasks.json`

### 4. 执行 Agent

#### HTML 子 Agent

- 调用 `resources/skills/html-animation/`
- 需要时接入 `resources/references/hyperframes/` 中保留的 skills、registry 与规范资产
- 负责概念图解、流程说明、类 UI 科普片段

#### Manim 子 Agent

- 调用 `resources/skills/manim/SKILL.md` 对应能力
- 负责公式推导、几何直觉、坐标系、函数变化、证明要点

#### SVG 子 Agent

- 当前作为二阶段能力预留
- 负责对复杂矢量示意动画进行补充

### 5. 审核 Agent

职责：

- 核对数学事实
- 检查脚本与分镜一致性
- 检查镜头时间轴与字幕/配音是否可拼接
- 输出通过或阻塞结论

### 6. 后处理器

职责：

- 配音生成
- 字幕对齐
- 片段拼接
- 输出交付

## 四、状态机

```text
PRESTART
  -> INGEST
  -> SUMMARIZE
  -> PLAN
  -> DISPATCH
  -> REVIEW
  -> POST_PRODUCE
  -> PACKAGE
  -> DONE

任一阶段失败
  -> BLOCKED
```

每个阶段都要写入：

- 当前状态
- 输入清单
- 输出清单
- 阻塞原因
- 下一跳建议

## 五、上下文分层

### 长期上下文

用于项目级事实和可复用决策：

- 论文总结
- 术语表
- 公式目录
- 风格规范
- 已批准分镜
- 审核结论

### 短期上下文

用于镜头级协作：

- 子 Agent 局部草案
- 临时解释
- 单次重试记录
- 局部失败痕迹

详细格式见 [上下文与状态设计.md](/C:/Users/84025/Desktop/ManiMind/docs/上下文与状态设计.md)。

## 六、关键数据流

```text
论文 PDF + 笔记
-> 主 Agent 研究总结
-> 二级协调 Agent 讲解脚本 / 分镜 / 任务切分
-> HTML / Manim / SVG 子 Agent 并发产出
-> 主 Agent 汇总
-> 审核 Agent 判定
-> 配音 / 字幕 / 拼接
-> 成片与交付包
```

## 七、外部能力接入策略

### HTML 侧

- 先用 `resources/skills/html-animation/` 生成或重构 HTML 片段
- 再参考 `resources/references/hyperframes/` 中保留的 skills、registry 片段与 HTML 规范做校验和收敛

### Manim 侧

- 以 `resources/skills/manim/SKILL.md` 为准组织场景脚本、字幕策略和语音同步策略
- 项目内只保存调用参数、任务协议和产物索引

### SVG 侧

- 先定义接口与产物契约
- 二阶段再接具体生成器

## 八、初始化建议

当前仓库先采用“单仓编排层 + 外部能力目录”的轻量单体架构：

- 优点：最快落地，便于追踪，适合早期迭代
- 代价：后续若任务编排变复杂，需要拆分 `ingest`、`review`、`render` 等模块

因此当前初始化重点不是做微服务，而是先把：

- 文档
- 目录结构
- 状态模型
- 初始化脚本
- 环境检测

这几件事打牢。
