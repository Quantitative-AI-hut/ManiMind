# ManiMind 审核与代码审计标准

本文件对应项目中的“审核 Agent”职责，也用于人工审阅代码和流程设计。

## 一、审核对象

- 研究总结是否忠于论文和笔记
- 讲解脚本是否适合目标受众
- 分镜是否完整覆盖脚本叙事
- HTML 片段与 Manim 片段是否各自承担合适任务
- 字幕、配音、片段拼接是否存在时间轴冲突
- 项目代码是否违背仓库既定边界

## 二、审核关卡

### P0 数学正确性

- 公式、定理、推导关系不能与原论文冲突
- 如做科普简化，必须明确是“解释性转述”而不是“原式替代”
- 审核不通过时禁止进入后处理

### P0 结构完整性

- 输入资产、总结、脚本、分镜、任务清单、审核结论缺一不可
- 任一镜头没有素材归属或没有责任 Agent，都视为失败

### P1 渲染可执行性

- HTML 任务必须标明依赖 `resources/skills/html-animation/` 或 `resources/references/hyperframes/` 的哪个入口
- Manim 任务必须标明公式、镜头目标和时长预算
- 缺失工具链时，必须给出阻塞原因，不能假装成功

### P1 时间轴一致性

- 脚本时长总和要和镜头总时长可对齐
- 字幕、配音、镜头切换不能互相覆盖或错位

### P2 风格一致性

- 长期上下文中的风格规范要对所有镜头生效
- HTML 片段、Manim 片段、SVG 片段的视觉语言不能完全割裂

## 三、代码审计重点

1. 是否把外部依赖当黑盒接入，而不是复制重写
2. 是否把长期与短期上下文混用
3. 是否有无生命周期的缓存或隐藏状态
4. 是否有无法追踪来源的任务分发规则
5. 是否存在“审核失败仍继续执行”的路径

## 四、建议输出格式

审核 Agent 或人工审阅结果建议包含：

- 结论：通过 / 阻塞 / 需修改
- 严重问题列表
- 受影响镜头或模块
- 建议修复动作
- 是否允许进入后处理
